Chat 6 Pro has undocumented GitHub connector limits on write actions, somewhere between 200 and 300 actions per week. Advanced agentic development tasks can consume 10-80 writes in a single chat turn. However, that doesn't mean you can't do work with 6, then publish with Sol/ExtraHigh.
These prompt appendations instruct pro6 to not attempt write actions, in order to save the weekly allocation for other tasks, or to continue after you hit the limit. Without these instructions, work will usually finish in a publishable state, however by including these specific directions, you ensure that a better state is achieved while also saving tokens, context and time by avoiding doomed attempts.

Append this:
GitHub publication handoff: Do not attempt any GitHub write or mutation actions in this run. Treat the GitHub connector as read-only. Continue the task normally using all available read, inspection, local checkout, editing, build and test capabilities; do not stop merely because publication is unavailable. Where possible, complete the implementation fully in the local working tree and leave it in a coherent, tested, publication-ready state.
At the end, prepare an exact handoff for Sol5.6 to publish the work. Preserve the working state and record everything needed to continue without repeating investigation: current base SHA, branch/worktree state, files changed, tests run and results, remaining verification, intended branch/commit message, PR title/body, issue updates/closures, merge conditions, and any other required GitHub mutations. The handoff should tell Sol5.6 to reconcile live state once, then perform only the outstanding publication/landing work and any necessary final fixes.

A slightly tighter version, if prompt length matters:
Publication constraint: Do not attempt GitHub writes. Use GitHub read-only, but otherwise complete the task as far as possible locally: inspect, edit, build, test and leave the working tree publication-ready. Do not stop simply because connector mutation capability is unavailable.
Finish with a precise Sol5.6 handoff containing the base SHA, branch/worktree state, changed files, test/evidence results, remaining checks, commit/branch/PR metadata, issue updates and exact outstanding GitHub actions. Sol5.6 should be able to take over immediately, reconcile live state once, and publish/land the prepared work without redoing the investigation.
